# BI Python Pipeline Validation

_Last updated: 2025-02-14_

## Summary
- Stage 07 BI prep now runs exclusively via `src/app/services/stage_07_bi_prep_python/impl.py`.
- Historical folder names (`phase_07_knime`, `stage_07_knime_bridge`) remain so `/api/bi` and downstream notebooks keep working unchanged.
- KNIME executables/scripts are no longer invoked by the supported pipeline; any remaining scripts are marked as **DEPRECATED** for archival use only.
- Stage 08 emits a Python-native `advanced/` bundle (cluster/anomalies/correlation/forecast + summary) that replaces the legacy KNIME exports; `/api/bi/intelligence` now hydrates these files directly.
- Stage 09 business validation writes its own `gate.json`/`diagnostics.json`, and the BI API surfaces this context so dashboards see the exact readiness reasons (including NZV impact) without touching KNIME.

## Running Stages 01–10 locally
```
python3 cli/runner.py flow --run-id=bi-python-demo --run-stage07-analytics
```
This command ingests `data/basic.csv`, executes Stages 01→10, runs the Python analytics suite, and copies outputs to both `artifacts/bi-python-demo` and `artifacts/run-latest`.

## KNIME dependency audit
- **Runtime**: no module in Stages 06–10 shells out to `knime.exe` or `.knwf`. Environment flag `MINDQ_KNIME_MODE` is ignored unless explicitly provided for backward compatibility.
- **CLI**: `cli/runner.py` now enforces the Python BI prep mode and never warns about KNIME approvals.
- **Scripts**: `knime/run_knime_workflow.ps1` and `scripts/knime_approval.ps1` are tagged as `DEPRECATED`; they are excluded from the normal BI flow but retained as docs.
- **Docs**: this page plus `docs/KNIME_BRIDGE_OVERVIEW.md` point readers to the Python flow and clarify the remaining legacy names.
